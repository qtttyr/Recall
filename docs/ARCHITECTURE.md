# Architecture

Recall is a menu-bar application with one primary surface: a non-activating
`NSPanel` that appears over the current app. The code is deliberately split
between a small AppKit shell and a SwiftUI/actor core, with no external
dependencies.

## Module map

| Area | Files | Responsibility |
| --- | --- | --- |
| App shell | `Recall/App/AppDelegate`, `RecallApp`, `AppState` | Lifecycle, dependency graph, menu bar, hot key, onboarding/settings windows |
| Panel | `Recall/App/PanelController`, `Recall/Features/Panel/*` | Borderless panel, key handling, query state, result rendering |
| Capture | `Recall/Core/Capture/ClipboardMonitor` | Pasteboard change polling, privacy gates, candidate construction |
| Model | `Recall/Core/Model/*` | `ClipItem`, `ItemKind`, `ClipCandidate`, content classification |
| Permissions | `Recall/Core/Permissions/Permissions` | Pasteboard access, Accessibility, `⌘V` posting, protected writes |
| Storage | `Recall/Core/Storage/*` | SQLite wrapper, schema, FTS5, embeddings, pruning, export |
| Search | `Recall/Core/Search/*` | Query parsing, BM25, semantic engine, vector matrix, model lifecycle |
| Settings | `Recall/Core/Settings/AppSettings` | Observable, `UserDefaults`-backed preferences |
| Design | `Recall/Design/*` | Theme, glass background, hosting helpers |
| Onboarding | `Recall/Features/Onboarding/*` | Three fixed-height steps and model readiness |
| Settings UI | `Recall/Features/Settings/*` | Model, privacy, history, excluded apps |

## Startup

1. `AppDelegate` sets the activation policy to `.accessory` and constructs
   `AppState`.
2. `AppState` opens `ClipStore`, creates `SemanticEngine`, `ModelManager`,
   `VectorIndex`, `SearchEngine`, `ClipboardMonitor`, and `PanelController`.
3. `start()` installs the menu bar item and Carbon hot key, starts the
   clipboard monitor, starts the semantic index loop, and asks
   `ModelManager.checkAtLaunch()` to activate a cached model.
4. Onboarding is shown until `hasCompletedOnboarding` is set. The model step
   can trigger the download; the download task belongs to `ModelManager`, not
   the view, so closing onboarding does not cancel it.

## Capture pipeline

`ClipboardMonitor` polls `NSPasteboard.general.changeCount` every 350 ms. It only
reads pasteboard contents after the counter changes. Before reading, it drops
the event when any of these are true:

- capture is paused;
- the app does not have pasteboard access;
- secure keyboard entry is active;
- the change came from Recall's own write (a private pasteboard marker);
- the pasteboard contains `org.nspasteboard.ConcealedType`,
  `TransientType`, or `AutoGeneratedType`;
- the frontmost app is excluded or is Recall itself.

Images are preferred when the pasteboard exposes image bytes; otherwise a file
URL becomes a link. The candidate is classified as text, code, link, or image
and written through `ClipStore.insert`. Re-copying the same content refreshes
its timestamp rather than creating a duplicate.

## Storage

SQLite runs in WAL mode with a hand-rolled wrapper. The schema has one `items`
table plus an external-content FTS5 table:

```text
items(id, kind, text, source_app, source_bundle, created_at, favorite,
      content_hash UNIQUE, image_path, embedding, embedding_language,
      embedding_provider)
items_fts(text) USING fts5(content='items', content_rowid='id',
                           tokenize='unicode61 remove_diacritics 2')
```

Triggers keep FTS in sync on insert, delete, and text update. `user_version` is
1. A startup check rebuilds FTS if its row count drifts from `items`.

`ClipStore` is an actor. Every database operation returns value types and the
UI never blocks on disk I/O. Images are stored as PNG files outside the
database and referenced by path.

Embeddings are stored as raw `Float` bytes with the provider ID and language
bucket. This makes a provider switch safe: old vectors are ignored and
recomputed, never mixed with a different embedding space.

## Search pipeline

1. `SearchQueryParser` extracts explicit filters (`#code`, `type:link`,
   `#image`, `#fav`), natural date ranges (`вчера`, `yesterday`, `last week`),
   and a free-text remainder. It also builds the FTS expression.
2. Keyword retrieval uses FTS5 with meaningful tokens only. Tokens shorter than
   two characters and common function words are dropped, and remaining tokens
   are joined with `AND` and prefix matching. This is the precision path; a
   natural-language sentence is allowed to produce no keyword matches.
3. Semantic retrieval embeds the query with the search prompt, searches the
   in-memory matrix for the matching language bucket, applies an absolute floor
   and a top-relative margin, loads the matching items, and applies any
   explicit date/kind filters.
4. The semantic item set is authoritative. Keyword hits are intersected with
   it before reciprocal-rank fusion, so keyword matches can reorder the close
   matches but cannot introduce unrelated items. If semantic retrieval is empty
   or unavailable, keyword results become the fallback.
5. The fused list is capped at **5** results. Recent history shows **6** when
   the query is empty.

The relative cutoff is what keeps the panel honest. EmbeddingGemma's similarity
scale is compressed: unrelated notes can score around 0.60. An absolute
threshold alone would either reject good matches or keep everything. The
current bounds are:

| Provider | Absolute floor | Top-relative margin |
| --- | --- | --- |
| EmbeddingGemma 2 | 0.58 | 0.10 |
| Apple contextual | 0.55 | 0.10 |

These live in `SemanticEngine.relevanceBounds()` and are intentionally not
user-facing knobs.

## Vector index

`VectorIndex` is an actor holding one contiguous `[Float]` matrix per language.
Each row is a normalized embedding. Search is a BLAS `sgemv` pass followed by a
sort. For a clipboard history the scale is small (tens of thousands of short
items), so brute force is simpler and more predictable than maintaining an ANN
index.

`rebuild(from:provider:)` loads only vectors for the active provider. The app
index loop writes new embeddings in batches and upserts them into the matrix.
Provider changes restart the loop and rebuild the matrix.

## Model lifecycle

`ModelManager` is a MainActor observable state machine:

```text
unknown → checking → absent | partial | downloading → verifying → compiling
        → loading → ready
                    ↘ failed
```

- `checkAtLaunch()` trusts a completed, stamped cache (`recall-revision`) and
  activates it without re-hashing every byte.
- `download()` resumes partial assets, verifies each file with SHA-256, installs
  atomically, compiles the `.mlpackage`, and loads the compiled model.
- `verify()` recomputes the digests on demand.
- `remove()` unloads the model and deletes the cache; semantic search falls back
  to Apple's contextual embeddings.

On provider change, `AppState.searchProviderChanged()` cancels the old index
task, rebuilds the vector index for the new provider, and re-embeds items whose
provider does not match.

## UI

The panel is a borderless, non-activating `NSPanel` with a transparent
background and a SwiftUI hosting view. It can become key (for the text field)
but not main. The panel uses the mouse's screen, positions itself above the
vertical center, and hides on deactivation.

`PanelController` handles key codes at the AppKit level so navigation works
before the text field consumes events. `PanelModel` debounces semantic queries
by 130 ms, cancels stale tasks with a generation counter, and never writes an
old provider's vectors back into the new state.

`GlassBackground` uses SwiftUI's `glassEffect` on macOS 26+ and falls back to
`NSVisualEffectView` plus a hand-tuned gradient on earlier systems. The
snapshot harness forces the legacy path because `cacheDisplay` cannot sample a
live desktop material.

## Concurrency

The project uses Swift 6 with complete strict concurrency and nonisolated
default isolation.

- UI and app state are `@MainActor`.
- `ClipStore`, `SearchEngine`, `SemanticEngine`, and `VectorIndex` are actors.
- Core ML calls run off the main actor; the model object is `Sendable`.
- Search tasks are cancelled and generation-checked when the query changes.
- Embeddings from an old provider are rejected at write time.

## Debug-only tooling

The following are compiled only in `DEBUG`:

- `RECALL_MODEL_SELFTEST=1` downloads/loads the model and prints cross-language
  similarity scores.
- `RECALL_SNAPSHOT_MODE=panel|onboarding|settings` renders a representative
  window to `RECALL_SNAPSHOT_PATH`.
- `RECALL_DEBUG_DATA=1` uses a temporary database so snapshots do not touch the
  real history.
- `RECALL_SNAPSHOT_LEGACY_GLASS=1` forces the pre-26 glass path for captures.

These are development aids, not supported product flags.

## Invariants

- No clipboard content leaves the Mac for embedding.
- The semantic result set is authoritative when it exists.
- Vectors are never compared across providers or dimensions.
- A failed capture or index write never interrupts the user's copy.
- Concealed, transient, secure, excluded, and self-originated copies are never
  stored.
- The app is usable before the optional model is downloaded.
